AL-thmany 2.7.2 — Test & Repair Report
======================================

Reference reviewed
------------------
- AL-thmany 2.5.1 GitHub-ready source and Event-First Fast-UI patch/report.
- Preserved proven event-first timing: 14ms event, 36ms stable, 95ms fallback, 40ms watchdog, 68ms click throttle, 18ms gesture, 120ms retry, 35ms post-Join evidence, 0ms next-link settle.

Root causes addressed
---------------------
1. Personal mode could report Accessibility configured while the current app process had no connected QuickJoinAccessibilityService.
2. A persisted developer Shadow flag could classify Join at confidence 100 but intentionally suppress every click.
3. Shizuku trusted only the shell exit code even though ActivityManager can print a semantic launch error with exit code 0.
4. A failed package-only deep link could leave Launcher/SystemUI in front until a continuity timeout.

Implemented repair
------------------
- Accessibility readiness now uses an in-process live service connection flag set by onServiceConnected and cleared by onUnbind/onDestroy.
- AccessibilityManager or a live callback can establish configured state; a stale Settings.Secure entry can no longer establish local readiness.
- The direct Accessibility details route now passes the flattened component string used by Android's own AccessibilityManagerService.
- One-time 2.7.2 migration clears persisted Shadow mode; every explicit Start clears it again before backend selection.
- Added ShizukuLaunchPolicy to reject exit failures, Error, SecurityException, Permission Denial, unable-to-resolve, missing activity, and no-handler launch results.
- Failed deep-link launches retry once through Android's exact resolved WhatsApp VIEW activity.
- A recovered exact activity is cached for later links while exact user/package locking stays mandatory.
- Existing bounded 1.1s foreground recovery, 1.2s no-root advance, 1.6s UI-tree advance, 2s unknown guard, 20s Loading guard, and Restriction hard stop remain active.

- Device-level WhatsApp UI behavior still requires the supplied 3-link acceptance test on the exact Samsung firmware and in each Android profile. The update does not claim to bypass Work Profile, Knox, Shizuku, Android Accessibility, or WhatsApp restrictions.

----------------------------
