AL-thmany 2.4.0 — Native Multi-Profile Engine
Test Report
Date: 2026-08-10

Scope implemented
- Profile-aware native engine router for OWNER / MANAGED_WORK / SAMSUNG_ISOLATED / SECONDARY.
- Local Accessibility remains first choice when the service is connected in the same profile.
- Guarded Shizuku is the native fallback when available; its existing package/foreground/UI-dump/tap guards remain enforced.
- Shizuku Android-user resolution now locks to the exact UID of the currently running AL-thmany process before requiring the target WhatsApp package in that same user. It no longer selects the first user that merely contains both package names.
- Optional WorkProfileAdminReceiver / WorkProfileController added. It can adjust the permitted Accessibility package allowlist only when Android has actually provisioned AL-thmany as Profile Owner or Device Owner.
- Existing Work Profiles owned by another DPC are never adopted or bypassed.
- Work Controller does not programmatically enable Accessibility; Android/user activation is still required.
- Secure Folder / Knox is not bypassed. If neither local Accessibility nor a successful Shizuku runtime is available, the run is not guessed or forced cross-profile.
- WhatsApp restriction/retry-later hard stop is preserved.
