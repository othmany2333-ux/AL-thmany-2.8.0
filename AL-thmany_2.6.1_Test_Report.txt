AL-thmany 2.6.1 — Unstoppable Sequential Continuity

Scope
- Base: AL-thmany 2.6.0 Accessibility Parity Fast Path.
- Target backend: SHIZUKU_FAST_UI_ACTIVE in Work Profile / secondary Android users.
- Goal: keep the explicit queue moving sequentially through conversations, unknown/ambiguous UI, foreground loss, transient missing root, UI-tree failures and repeated input failures without low-confidence taps.

Implemented continuity behavior
- Zero-delay direct next-link handoff remains enabled.
- Post-Join conversation still verifies success and launches the next deep link directly.
- Direct conversation without a pending Join is accepted as ALREADY_MEMBER only after a new target-package UiAutomation event newer than that link's launch baseline; this avoids treating the previous chat as the new link result.
- Foreground loss: exact-user deep link reacquisition is attempted twice; after the bounded budget the current link is recorded UNKNOWN_SCREEN and the queue advances.
- Persistent NO_ROOT: current link is advanced safely after the continuity budget instead of hanging indefinitely.
- Command UI-tree failure: bounded safe advance instead of terminating the run.
- Ambiguous action exhaustion: no guessed tap; current link is recorded UNKNOWN_SCREEN and the queue advances.
- STOP_UNKNOWN: converted to safe continuity advance.
- Repeated input failures: service stays alive; bounded retry/watchdog logic remains authoritative.
- Temporary Shizuku disconnect: current link is preserved while the service waits for reconnect.
- Genuine Loading remains protected by its separate 20-second timeout.
- Restriction / Retry Later remains a hard stop and is not bypassed.
- User Stop/Pause, session completion, invalid profile/target lock and unrecoverable repository/session faults remain structural stop conditions.
